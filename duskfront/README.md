# جبهة الغسق — DUSKFRONT

**لعبة حرب ويب ثلاثية الأبعاد على كوكب يدور ببطء، حيث الضوء نفسه سلاح ومورد.**
*A 3D web war game on a slowly rotating planet, where light itself is a weapon.*

</div>

---

## الفكرة

على كوكب **نَهار**، يزحف **خط الغسق** — الحد الفاصل بين الليل والنهار — عبر الخريطة من الغرب
إلى الشرق بسرعة **1.33 م/ث**، فيعبرها كاملة خلال العشرين دقيقة التي تستغرقها المباراة. النتيجة أن
ساحة المعركة تعيد تشكيل نفسها تحت أقدامك:

| المنطقة | الميزة | العقوبة |
|---|---|---|
| **السطوع** | الأسلحة الشمسية تُشحن ×2 | ضرر حرارة 4/ث بعد 20 ثانية تعرّض متواصل |
| **الشفق** (250م) | منطقة آمنة، شحن ×1 | أكثر المناطق انكشافًا وتنازعًا |
| **العتمة** | تخفٍّ: تختفي من الخريطة المصغّرة ومن فوق الرؤوس بعد 15م | لا شحن شمسي، وضرر برد 2/ث بعد 30 ثانية |

ومن هذا تنبع الآليتان الأساسيتان:

1. **القلعة الزاحفة** — قاعدة متحركة عملاقة لكل فريق يجب أن تبقى داخل شريط الشفق، وإلا خسرت 1%
   من متانتها كل ثانية بعد مهلة عشر ثوانٍ. يقودها الفريق بالتصويت.
2. **التلاعب بالضوء** — **مرايا** توجّه شعاع الشمس إلى العتمة فتكشف المتخفّين وتشحن الحلفاء،
   و**أبراج ظل** تصنع بقعة ظل داخل السطوع تحمي من الحرارة.

**شروط الفوز:** تدمير نواة العدو · أو أعلى متانة قلعة عند انتهاء الوقت · أو إبقاء قلعة العدو خارج
الشفق حتى تنهار.

## التشغيل السريع

### الخيار ١ — Docker (كل شيء بأمر واحد)

```bash
cp .env.example .env          # عدّل الأسرار قبل الإنتاج
docker compose up             # web + server + postgres + redis + نسخ احتياطي يومي
```

- اللعبة: <http://localhost:8080>
- الخادم: <http://localhost:2567/health>

الترحيل والبذر يجريان تلقائيًا (`RUN_MIGRATIONS=true`, `RUN_SEED=true`). لتشغيلهما يدويًا:

```bash
npm run migrate && npm run seed
```

### الخيار ٢ — محليًا بلا أي بنية تحتية

اللعبة تعمل كاملة **بلا Postgres ولا Redis**: إن غاب `DATABASE_URL` يستخدم الخادم مخزنًا داخل
الذاكرة، وإن غاب `REDIS_URL` يستخدم ذاكرة مؤقتة داخلية. هذا يجعل أول تشغيل بلا احتكاك:

```bash
npm install
npm run dev        # يبني الحزمة المشتركة ثم يشغّل الخادم والعميل معًا
```

- العميل: <http://localhost:5173>
- الخادم: <http://localhost:2567>

> ⚠️ المخزن الداخلي للتطوير والاختبار فقط — البيانات تضيع عند إعادة التشغيل، والخادم يرفض الإقلاع
> في `NODE_ENV=production` بلا `DATABASE_URL` أو بأسرار JWT الافتراضية.

## البنية

```
duskfront/
├─ packages/shared/          ← المحاكاة المشتركة: مصدر الحقيقة الوحيد لقواعد اللعبة
│  └─ src/
│     ├─ balance.json        ← كل أرقام التوازن (انظر أدناه)
│     ├─ terrain.ts          ← تضاريس إجرائية حتمية (نفس الدالة للرسم والاصطدام)
│     ├─ dusk.ts             ← خط الغسق، المناطق، مستوى الضوء L، الحرارة والبرد
│     ├─ physics.ts          ← محرّك حركة الشخصية + الأشعة
│     ├─ weapons.ts          ← الضرر، سقوط المسافة، إصابات الرأس
│     └─ sim/                ← المحاكاة الموثوقة + البوتات + شبكة التنقّل
├─ apps/server/              ← Fastify (REST) + Colyseus (20Hz) + Prisma + مكافحة الغش
├─ apps/client/              ← Vite + Three.js + الواجهة + الصوت + المدخلات
├─ prisma/                   ← المخطّط + الترحيلات + البذر
└─ tests/                    ← وحدات (Vitest) + شامل (Playwright)
```

### لماذا تعيش المحاكاة في حزمة مشتركة؟

لأن **الخادم والعميل يشغّلان الكود نفسه حرفيًا**:

- الخادم يشغّل `MatchSimulation` كمرجع موثوق عند 20Hz.
- العميل يشغّل **نفس** `stepCharacter` للتنبؤ المحلي، فيتقارب التصحيح بدل أن يتذبذب.
- أوضاع **الحملة والتدريب والمناوشة** تشغّل `MatchSimulation` كاملة داخل المتصفّح — فهي تمرين
  حقيقي على اللعبة لا نسخة مبسّطة منها، وتعمل بلا خادم أصلًا.

## تعديل التوازن

**قاعدة صارمة: كل رقم توازن يعيش في `packages/shared/src/balance.json` ولا يُكتب في الكود.**

```bash
# ١) عدّل الملف
$EDITOR packages/shared/src/balance.json

# ٢) أعد توليد وحدة TypeScript المضمّنة (تعمل تلقائيًا مع البناء)
npm run gen:balance -w @duskfront/shared

# ٣) أعد البناء
npm run build:shared
```

> **لماذا التوليد؟** استيراد JSON مباشرة يحتاج `import attributes` في Node ESM ويتعامل معه كل
> مجمِّع بطريقة مختلفة. التوليد يجعل نفس الأرقام تصل إلى Node والمتصفّح بلا حيل خاصة بكل بيئة.
> `balance.json` يبقى الملف الذي تحرّره؛ الملف المولَّد لا يُحرَّر يدويًا.

الدالة `assertBalanceIntegrity()` تعمل عند إقلاع الخادم وتفشل بسرعة إن كان الملف متناقضًا (صنف
يشير إلى سلاح غير موجود، بئر خارج الخريطة، أو سرعة غسق لا تعبر الخريطة في مدة المباراة).

## الاختبارات

```bash
npm test              # 145 اختبار وحدة
npm run coverage      # مع تقرير التغطية
npm run e2e           # 6 اختبارات شاملة بمتصفّح حقيقي
npm run typecheck     # فحص الأنواع للحزم الثلاث
```

**التغطية الحالية:** 75% أسطر · 78% تفرّعات · 75% دوال — فوق عتبة الـ70% المطلوبة.
منطق اللعبة نفسه أعلى: `packages/shared` عند **88%** و`sim/` عند **80%**.

الاختبار الشامل يغطّي المسار المطلوب: **التسجيل ← مباراة ← الحفظ ← إعادة التحميل والبيانات باقية**.

في البيئات التي تملك Chromium مثبّتًا مسبقًا:

```bash
DUSKFRONT_CHROMIUM=/path/to/chromium npm run e2e
```

## تعديلات مقترحة على المواصفات (ولماذا)

هذه انحرافات واعية عن نصّ البرومبت، كل واحدة لسبب هندسي:

| المواصفة | ما نُفِّذ | السبب |
|---|---|---|
| فيزياء `@dimforge/rapier3d-compat` | محرّك حركة مصغّر داخل `packages/shared/src/physics.ts` | التنبؤ والتصحيح يتطلّبان نتيجة متطابقة بين Node والمتصفّح. WASM يضيف حملًا ولا يضمن الحتمية عبر البيئات. المحرّك الحالي يصل إلى السرعة المقصودة بالضبط أيًا كان معدّل التحديث (مُختبَر عند 20/60/144Hz). |
| `recast-navigation-js` للتنقّل | شبكة تنقّل + A* في `sim/navgrid.ts` | التضاريس دالة تحليلية، فشبكة مبنيّة من ميل السطح دقيقة ورخيصة ولا تحتاج خطوة توليد navmesh. |
| — | **مخزن داخل الذاكرة** كبديل تلقائي لـPostgres/Redis | يجعل `npm run dev` و145 اختبارًا يعملان بلا بنية تحتية. الإنتاج يفرض Postgres. |
| — | **الأوضاع المحلية** (حملة/تدريب/مناوشة) تعمل بلا خادم | نفس المحاكاة، فاللعبة قابلة للعب فورًا وحتى دون اتصال. |
| مسار `/matchmake` | `/api/queue` | Colyseus يعترض أي مسار يحتوي السلسلة `/matchmake` على مستوى خادم HTTP. |
| ظلال متتالية (CSM) | ظل اتجاهي واحد عالي الدقة + ضباب واعٍ بالمنطقة | CSM الكامل يتجاوز ميزانية 300 نداء رسم على الجوال؛ المشهد مفتوح ونطاق الظل المفيد قصير. |

### ما لم يُنفَّذ بالكامل

- **تحميل تدريجي للأصول:** الحزمة الأولى **264KB مضغوطة** (أقل بكثير من حد 15MB)، لأن كل الأصول
  مولَّدة برمجيًا — فلا حاجة لتحميل تدريجي أصلًا.
- **غرفة Colyseus** مغطّاة باختبار E2E لا باختبار وحدة (6% تغطية أسطر) — المحاكاة التي تغلّفها
  مغطّاة عند 80%.
- **لم تُختبر** مسارات Postgres/Redis على قاعدة بيانات حيّة في هذه البيئة (لا يوجد Docker daemon)؛
  تحقّقنا منها بفحص الأنواع، ومخطّط Prisma صالح، والترحيل الأوّلي مولَّد. المنطق نفسه مُختبَر
  بالكامل عبر محوّل الذاكرة الذي يطبّق الواجهة نفسها.

## الأمان

- كلمات المرور بـ **argon2id** (19MiB · timeCost 2) بمعاملات OWASP الدنيا.
- رمز وصول JWT مدته 15 دقيقة، ورمز تحديث **يُدوَّر عند كل استخدام ويُخزَّن مُجزّأً (SHA-256)**؛
  إعادة استخدام رمز مُبطَل تُبطل كل جلسات الحساب (كشف السرقة القياسي).
- **الخادم مصدر الحقيقة الوحيد**: لا يُقبل أي رقم من العميل. المكافآت والإحصاءات والعملة تُحسب
  على الخادم داخل معاملة واحدة، والرصيد يساوي مجموع سجل العملة دائمًا (مُختبَر).
- مكافحة الغش: تحقق من السرعة ومعدّل الإطلاق وسرعة الالتفات ونقطة الانطلاق، مع تجميع مخالفات
  وتلاشٍ زمني وحظر تلقائي مؤقت.
- تعويض التأخير بإرجاع زمني حتى 200ms — لا يستطيع العميل اختلاق إصابة لأن الخادم يعيد الحساب.
