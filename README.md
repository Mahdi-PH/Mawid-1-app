# Mawid (موعد)

نظام سحابي ومحلي متكامل (SaaS) لإدارة حجوزات العيادات الطبية الصغيرة والمراكز الصحية الخاصة، مصمم خصيصاً ليناسب بيئة العمل الطبية، مع التركيز على البساطة، العمل في ظروف انقطاع الإنترنت، القضاء على التكدس، وتقليل نسبة الغياب.

هذا المستودع يحتوي النسخة الأولية (MVP) — البنية والمنطق الأساسي جاهزان للتشغيل والتوسعة، وليسا مجرد تصميم نظري.

## البنية العامة (Monorepo)

```
apps/
  server/            Express + Prisma (Postgres) — REST API
    prisma/schema.prisma      نموذج قاعدة البيانات الكامل
    prisma/seed.ts            بيانات تجريبية (عيادة + طبيب)
    src/modules/
      scheduling/  →  محرك الجدولة انتقل إلى packages/shared (منطق نقي بلا اعتماديات)
      appointments/  حجز/تحديث حالة الموعد + الحماية من الحجز المزدوج
      patients/      بحث/إنشاء مريض بالهاتف
      doctors/       قائمة الأطباء وأوقات عملهم
      visits/        الزيارة والوصفة السريعة
      display/       API شاشة صالة الانتظار
      sync/          نقطة استقبال المزامنة من الأجهزة العاملة بدون إنترنت
      reminders/     مهمة WhatsApp الدورية لتذكير المرضى
  web/               Next.js 14 (App Router) + Tailwind — الاستقبال وشاشة العرض
    src/lib/offline/   IndexedDB (Dexie) + طابور المزامنة الخلفي
    src/lib/api/       طبقة القراءة/الكتابة المحلية أولاً (local-first)
    src/app/dashboard  لوحة تحكم الاستقبال (Timeline)
    src/app/display    شاشة صالة الانتظار (TV)
packages/
  shared/            أنواع TypeScript المشتركة + محرك الجدولة (Slot Engine) — نفس الكود يعمل على السيرفر وعلى المتصفح
```

## 1) قاعدة البيانات (`apps/server/prisma/schema.prisma`)

- **Clinic → Doctor → WorkingHour / BreakBlock**: كل طبيب له جدول أسبوعي (يوم + وقت بداية/نهاية) وفترات استراحة متكررة.
- **Patient**: الاسم، الهاتف، رمز/رقم الملف الاختياري.
- **Appointment**: تاريخ + وقت + `status` (`booked/arrived/in_progress/completed/cancelled/no_show`) + `queueNumber` (رقم الطابور المعروض في شاشة الانتظار).
- **Visit**: ملاحظة تشخيص + نص وصفة سريع، مرتبطة بالموعد.
- **SyncedOperation**: سجل idempotency لعمليات المزامنة القادمة من الأجهزة بدون إنترنت.

### الحماية من الحجز المزدوج على مستوى قاعدة البيانات

عمود `Appointment.slotLockKey` هو `` `${doctorId}|${date}|${startTime}` `` **فريد (`@unique`)** طالما حالة الموعد "تشغل" الوقت (كل الحالات ما عدا `cancelled`). عند الإلغاء تصبح القيمة `NULL`، وPostgres يسمح بعدد غير محدود من `NULL` في فهرس فريد — أي أن إلغاء الموعد يحرر الوقت تلقائياً لإعادة الحجز، بينما محاولتان متزامنتان لحجز نفس الوقت تفشل إحداهما بخطأ `P2002` يتحول إلى `SlotTakenError` (انظر `appointments.service.ts`).

## 2) محرك الجدولة الذكي (`packages/shared/src/slotEngine.ts`)

منطق نقي (بدون قاعدة بيانات) — لذلك يعمل على السيرفر **وعلى المتصفح أثناء انقطاع الإنترنت** بنفس الكود تماماً:

- `generateDaySlots(doctor, date)` — يقسّم ساعات العمل إلى فترات ثابتة (مثلاً 15 دقيقة) ويستبعد أي فترة تتقاطع مع استراحة.
- `getAvailableSlots(...)` — الفترات الحرة فقط (يتجاهل المواعيد الملغاة).
- `queueNumberForSlot(...)` — رقم الطابور = ترتيب الفترة في شبكة اليوم، دالة نقية بدون أي حالة سباق.
- `buildSlotLockKey(...)` — يبني (أو يُفرغ عند الإلغاء) مفتاح الحماية من الحجز المزدوج المستخدم في قاعدة البيانات.

اختبارات الوحدة: `packages/shared/src/slotEngine.test.ts` (11 اختبار، `npm run test --workspace=packages/shared`).

## 3) العمل بدون إنترنت (`apps/web/src/lib/offline`)

- **`db.ts`**: قاعدة بيانات IndexedDB محلية (عبر Dexie) تُطابق نموذج السيرفر تماماً (patients/appointments/visits/doctors + طابور مزامنة `syncQueue`).
- **مبدأ التصميم**: كل قراءة تأتي من IndexedDB مباشرة (محسوبة بنفس محرك الجدولة)، وكل كتابة (مريض جديد، حجز، تغيير حالة) تُكتب محلياً أولاً بمعرّف `uuid` فوري ثم تُضاف لطابور المزامنة — الاستقبال لا ينتظر الشبكة أبداً.
- **`syncEngine.ts`**: `flushQueue()` يرسل العمليات المعلقة إلى `POST /api/sync/push` بالترتيب، ويُعيد ربط المعرّف المحلي بمعرّف السيرفر الحقيقي عند النجاح. `initBackgroundSync()` يُفعَّل عند بدء التطبيق ويعيد المحاولة عند رجوع الاتصال (`online` event) وكل 20 ثانية (لتغطية الاتصالات المتذبذبة التي لا تُطلق الحدث بشكل موثوق).
- **الخادم (`sync.routes.ts`)**: كل عملية تحمل `opId` من الجهاز؛ إعادة إرسالها (بسبب انقطاع أثناء الاستجابة) لا تُنشئ سجلات مكررة بفضل جدول `synced_operations`.

## 4) لوحة تحكم الاستقبال (`apps/web/src/app/dashboard`)

- **Timeline** عمودية بكل فترات اليوم — فارغة (زر "+ حجز موعد") أو محجوزة (اسم المريض + شارة حالة ملونة + قائمة تغيير الحالة).
- **حجز مريض جديد في نقرتين فقط**: نقرة على فترة فارغة تفتح `QuickBookModal`، ثم نقرة "تأكيد الحجز" (بعد كتابة الاسم/الهاتف أو اختيار مريض من نتائج البحث الفوري بالهاتف) تُنشئ المريض (إن لزم) وتحجز الموعد في خطوة واحدة.
- ألوان الحالة (`APPOINTMENT_STATUS_COLORS` في `packages/shared`): رمادي = محجوز، كهرماني = في الانتظار، أزرق = عند الطبيب، أخضر = انتهى، فاتح باهت = ملغي/غياب.
- شارة أعلى الصفحة تُظهر "متصل/غير متصل" وعدد العمليات المعلقة بانتظار المزامنة.

## 5) شاشة صالة الانتظار (`apps/web/src/app/display` + `GET /api/display/now`)

- تعرض **رقم الطابور فقط** واسم الطبيب — **لا تُظهر اسم أو هاتف المريض أبداً** لحماية الخصوصية أمام غرفة مليئة بالغرباء.
- Polling كل 4 ثوانٍ (وليس WebSocket) لأن هذه الشاشة تعمل لساعات على شبكة عيادة قد تكون غير مستقرة — أي طلب فاشل يُعاد تلقائياً في الجولة التالية بدل الحاجة لمنطق إعادة اتصال.
- عند ظهور رقم جديد "يدخل الآن": نبضة بصرية (توهج + تكبير) + نغمة صوتية قصيرة عبر Web Audio API (بدون ملف صوتي خارجي).

## 6) تذكيرات واتساب الآلية (`apps/server/src/modules/reminders`)

- `whatsapp.service.ts`: عميل خفيف لـ WhatsApp Business Cloud API (Meta) — قابل يستبدل بمزود آخر (Twilio مثلاً) بتعديل ملف واحد فقط.
- `reminders.cron.ts`: مهمة مجدولة كل 15 دقيقة تبحث عن كل موعد يقع بعد `REMINDER_HOURS_BEFORE` ساعة (افتراضياً 3) ولم يُرسل له تذكير بعد، وترسل رسالة قالب واتساب، ثم تُعلّم `reminderSentAt` — فشل الإرسال لا يُعلّم الحقل فيُعاد المحاولة في الجولة التالية.

## التشغيل محلياً

```bash
npm install

# قاعدة البيانات
cp apps/server/.env.example apps/server/.env   # عدّل DATABASE_URL
npm run prisma:migrate                          # ينشئ الجداول
npm run prisma:seed --workspace=apps/server     # عيادة + طبيب تجريبي، يطبع clinicId

# الواجهة
cp apps/web/.env.local.example apps/web/.env.local
# ضع NEXT_PUBLIC_CLINIC_ID = الـ clinicId المطبوع أعلاه

npm run dev:server   # http://localhost:4000
npm run dev:web       # http://localhost:3000  (/dashboard و /display)
```

اختبارات محرك الجدولة: `npm run test --workspace=packages/shared`

## ما لم يُبنَ بعد (خارج نطاق الـ MVP الحالي)

- مصادقة/صلاحيات مستخدمي الاستقبال (تسجيل دخول، أدوار).
- تعدد العيادات فعلياً في واجهة واحدة (البنية تدعمه عبر `clinicId`، لكن الواجهة الحالية مصممة لجهاز استقبال مخصص لعيادة واحدة).
- Service Worker / PWA كامل لتخزين الأصول نفسها (JS/CSS) offline — العمل الحالي يغطي البيانات، لا الأصول الساكنة.
